# 줄임말·별명 연결 검토

검토일: 2026-10-18. 최초 배너 14행·캐릭터 26행 초안과 이후 사용자가 붙여준
두 원문 내용을 현재 KR 게임 데이터와 대조한 기록이다. 커뮤니티에서 실제로 사용되는지와 이름·ID가 맞는지는
별개로 표시한다. 사용 빈도, 성능 등급, 본능 투자 필요성은 이 검토의 범위가 아니다.

## 출처와 확인 범위

- 사용자가 제공한 정리표: 검토 대상 초안이며 검증된 별명 사전으로 취급하지 않는다.
- [냥코 줄임말 사전](https://arca.live/b/battlecat/46071094),
  [추가 줄임말 자료](https://arca.live/b/nyanko/74042366): 사이트 직접 조회는 실패했으나
  사용자가 두 글의 본문을 붙여 주어 해당 텍스트의 용례를 확인했다. 게시일·수정일과
  현재 웹페이지 일치 여부는 독립 확인하지 않았다. 원문의 댓글 요청·조작 지시 등은 실행 지침이 아니다.
- 데이터 대조: `Route.ball_kr.cats`의 모든 형태 이름·희귀도,
  `EventSeriesNames::Korean/Shortcuts`, 기존 MCP 검색 코드와 `character-notes.json`.
- 기존 검증 출처: [티어 자료의 ID 연결](gpt-tier-sources.md). 이미 확인한 연결만 재사용한다.

이 문서는 검토 기록이다. 승인한 별명은 `gpt-knowledge/character-aliases.json`에 ID와
출처로 유지하고, 일반 용어 안내는 `gpt-knowledge/glossary.md`로 제공한다.
한국어 축약은 정식 이름의 연속 부분 문자열일 필요가 없다. 문단→문어단지,
라길→라면의 길, 암테→아마테라스처럼 대상이 확인되는 표현을 등록한다.

## 반영 결과

- 62개 캐릭터 ID에 64개 별명을 출처와 함께 등록했다. 별도 JSON 사전으로 읽어 기존 티어 글 별명과 합쳐 사용한다.
  문단·라길·아이캣·카맨·암테·크놋·거북카와 백/흑 축제 캐릭터 별명도 같은 ID로 연결한다.
- MCP 캐릭터 검색, 목표 이름/ID 검증, 웹/MCP Multi의 Find 선택 검색과 배너의 캐릭터
  검색에서 같은 사전을 사용한다. 각 화면의 기존 희귀도·대상 제한은 유지하므로 일반 레어/슈레가 Find 목표 목록에 새로 추가되는 것은 아니다. 정식 표시 이름·슬롯·확률·계산 엔진은 바꾸지 않는다.
- 닼히·발공·마마마·페스나/페이트·에바/에반·스파·썸걸은 기존 배너 시리즈 검색에 연결한다.
  에바·스파·썸걸처럼 여러 시리즈인 표현은 후보를 유지한다. 하고축은 정확히 일치하는
  별명이 있으면 울하고축 부분 문자열보다 우선한다.
- 블아·쌍포노·쌍슬리는 집단 표현으로 안내하며 단일 캐릭터로 고정하지 않는다.
  드론·하데스·해커 같은 중의적인 원래 이름도 여러 대상을 합치지 않는다.
- 정식 형태명으로 이미 검색되는 표현은 중복 등록하지 않았다. 머라이언은 현재 데이터의 Mr.머 연결을 확인하지 못했고, 초밥은 대상이 애매해 보류했다. 기존에 연결된 쌍장성은 시시루와 코마리 한 캐릭터 ID를 유지한다.
- 적 유닛 별명은 뽑기 캐릭터에 등록하지 않는다. 메탈·저주·실드·특효의 단정적인 설명,
  옛 출시 예정·스테이지/아이템 수치·주관적 성능과 비하 표현은 별명 식별 정보에서 제외한다.
  흑포노는 원문의 ‘미출시’ 문구를 복사하지 않고 현재 존재하는 ID 706으로 확인한다.
- 커뮤니티·시점 의존 별명인 갤주·챈주는 출처의 용례에 따라 소돔·멜슈 기본형 ID에 연결한다.
  해당 표현에 성능 평가를 붙이지 않는다. 최초 초안에만 있던 부갤주·흙슬리 등은 자동 확정하지 않는다.

## 운영 반영 기준

1. 배너 별명은 시리즈로, 캐릭터 별명은 캐릭터 ID로 분리한다.
2. 모든 형태 이름으로 이미 검색되는 표현은 중복 등록하지 않아도 된다.
   정식 이름과 불연속인 한국어 축약도 현재 데이터의 대상이 명확하면 별명으로 등록한다.
3. 커뮤니티·시점에 따라 달라질 수 있는 밈은 확인한 원문 용례의 대상에만 연결한다.
   복수 대상·집단 표현은 단일 ID에 고정하지 않는다.
4. 새 별명 등록에는 실제 용례 출처와 검토일을 남기고, 이름·형태·속성은 기존 데이터에서 읽는다.
5. 사전 변경 시 이 검토표를 갱신하고 MCP 검색으로 단일/복수 결과를 검증한다.
