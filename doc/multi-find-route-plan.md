# `/multi` Find 최적 경로 탐색 계획

- 상태: **구현 및 로컬 검증 완료, 커밋/배포 전**
- 작성일: 2026-08-23
- 구현 기준 커밋: `47772b76557c33018e992213e6896c84333195c5`
- 구현은 새 Find asset 네 개에 격리하고 기존 파일은 데이터/상태 브리지만 최소 수정했다.

## 1. 목표

`/multi`에서 여러 이벤트와 목표 캐릭터를 선택하면 1A부터 시작해 제한된
`count` 안에서 목표를 얻는 최적 경로를 계산한다.

경로는 다음 행동을 함께 고려한다.

- 일반 단뽑(레어티켓 또는 단뽑과 같은 1회 진행)
- 중복 레어에 의한 R 열변경
- 통조림 11연 확정뽑기에 의한 G 진행 및 열변경
- 플래티넘·레전드 티켓으로 중복 레어 열변경을 방어하는 행동
- 플래티넘·레전드 티켓에서 허용된 목표 캐릭터를 직접 얻는 행동
- 선택한 이벤트 사이의 배너 변경

배열 표시는 지금처럼 브라우저에서 먼저 끝내고, Find 탐색은 별도의
백그라운드 작업으로 뒤이어 수행한다.

## 2. 구현 경계

- 기존 이벤트 필터 구현은 리팩터링하지 않는다.
- Find UI, 엔진, Worker, CSS는 새 asset으로 분리한다.
- 기존 Ruby `Gacha` 규칙을 Find 편의를 위해 변경하지 않는다.
- 근사 경로를 정확한 최적 경로 또는 `불가능`으로 표시하지 않는다.
- KR과 JP 이벤트를 하나의 실제 뽑기 경로로 섞지 않는다.

## 3. 용어

문서와 UI에서 `티켓`이라는 표현이 혼동되지 않도록 아래처럼 구분한다.

- **일반 단뽑**: 레어티켓 또는 동일하게 한 칸 진행하는 단뽑. 사용 1회당
  코스트 `+0.03`이다.
- **특수 티켓**: 플래티넘 티켓과 레전드 티켓. 서로 다른 재화와 풀을 쓰며,
  각각 사용 1회당 비용 `+2`다.
- **확뽑**: 통조림 11연 확정뽑기. 사용 1회당 비용 `+1`이며 사용 가능
  최대 횟수를 사용자가 지정한다.
- **목표**: 모달에서 선택한 모든 캐릭터. 경로가 성공하려면 전부 획득해야 한다.
- **특수 티켓 비허용 목표**: 선택한 일반/확정 이벤트에서만 목표 달성으로 센다.
- **특수 티켓 허용 목표**: 이벤트에서 얻어도 달성하며, 플래티넘 또는 레전드
  티켓에서 얻어도 달성한다. 특수 티켓 사용에는 항상 비용 `+2`가 붙는다.

## 4. Find UI 계약

### 4.1 Find 입력 상자

Seed 검색 상자 아래, 이벤트 멀티트랙 선택 상자 위에 별도 패널을 둔다.

별도 Find 제목은 표시하지 않고, 바깥 패널은 위 Seed 입력 패널과 같은
너비·높이·패딩을 사용한다. 왼쪽부터 다음 순서로 한 줄에 배치한다.

1. 캐릭터 필터 버튼
2. 검색 기준: `최소코스트`(기본값), `최단거리`, 또는 `균형`
3. 통조림 확뽑 최대 횟수 숫자 입력
4. 플래티넘 티켓 최대 횟수 숫자 입력(기본값 0)
5. 레전드 티켓 최대 횟수 숫자 입력(기본값 0)
6. 선택한 캐릭터를 `a, b, c` 형태로 보여주는 읽기 전용 영역
7. 검색 기준을 설명하는 `?` 버튼

숫자 입력, 검색 기준, 선택 캐릭터 영역은 위 Seed 입력 패널과 같은 밑줄형
스타일을 사용한다. 제목 옆 부제와 패널 아래 설명 문구는 표시하지 않는다.

Find 설정을 변경하면 기존 상단 Apply 버튼이 다시 활성화된다. Apply를 누르면
기존 Track A/B 배열을 즉시 다시 그리고 그 후 Find 계산을 시작한다. Find 전용
Apply 버튼은 첫 구현에 추가하지 않는다.

### 4.2 캐릭터 선택 모달

이벤트 필터 모달과 동일한 기본 구조를 사용한다.

- 상단: 캐릭터명 검색
- 중앙: 선택된 캐릭터
- 하단: 선택 가능한 캐릭터 태그
- 표시 희귀도: 슈퍼레어, 울트라 슈퍼레어, 레전드 레어
- 현재 선택한 이벤트 풀에 존재하는 캐릭터를 앞에 정렬
- 그 밖의 대상 캐릭터도 검색 및 선택 가능
- 닫기, 바깥 영역 클릭 모두 현재 선택을 유지한 채 모달을 닫음

선택된 캐릭터 한 개는 내부적으로 다음 두 축을 별도로 가진다.

```text
TargetSpec {
  cat_id,
  allow_ticket    // 플래티넘·레전드 티켓 획득 허용 여부
}
```

권장 표시 형태:

```text
[특수 티켓 비허용 ▼] 아쿠아슈터 사키  ×
[특수 티켓 허용 ▼]   명계의 칼리파    ×
```

- 선택한 캐릭터는 모두 필수 획득 목표다.
- `특수 티켓 비허용`이면 두 티켓 결과로는 같은 캐릭터가 나와도 목표 달성으로
  세지 않는다.
- `특수 티켓 허용`이면 일반 이벤트와 두 특수 티켓 결과를 모두 목표 달성으로 센다.
- 같은 최종 위치에서는 비용 비교로 이벤트 획득이 특수 티켓 획득보다 우선한다.
- 더 가까운 특수 티켓 경로와 더 먼 이벤트 경로라면 기존 최적화 계약대로 최종
  위치가 먼저인 `최단거리` 모드에서는 가까운 특수 티켓 경로가 우선한다.
- `최소코스트` 모드에서는 더 먼 이벤트 경로의 총 코스트가 낮으면 이벤트
  경로가 우선한다.
- 플래티넘과 레전드 티켓은 최대 횟수를 독립적으로 제한한다. 해당 티켓 최대
  횟수가 0이면 그 티켓의 목표 획득과 R 방어 분기를 생성하지 않는다.

### 4.3 브라우저 저장

Find 상태는 기존 멀티트랙 상태와 분리된 `localStorage` 키에 저장한다.

- `optimization_mode: distance | cost | balance`
- `max_guaranteed`
- `max_platinum`
- `max_legend_ticket`
- `targets: [{cat_id, allow_ticket}]`

캐릭터 이름은 저장하지 않고 ID만 저장한다. 이름 변경이나 KR/JP 카탈로그 갱신
후에도 현재 데이터를 다시 표시할 수 있어야 한다.

## 5. 최적 경로 정의

목표를 모두 획득한 경로만 후보가 된다. 총 코스트는 정수 100분율로 계산해
부동소수점 비교 오차를 피한다.

```text
총 코스트 = (레어티켓 횟수 × 0.03)
            + (플래티넘 티켓 횟수 × 2)
            + (레전드 티켓 횟수 × 2)
            + (확뽑 횟수 × 1)
```

`최단거리` 모드 비교 순서:

```text
1. 최종 도달 위치
2. 총 코스트
3. 안정적인 내부 탐색 순서
```

`최소코스트` 모드 비교 순서:

```text
1. 총 코스트
2. 최종 도달 위치
3. 안정적인 내부 탐색 순서
```

`균형` 모드는 최소코스트와 같은 순서로 비교하되 경로에서 획득한 울슈레와
레전드레어를 다음처럼 보상한다.

```text
균형 코스트 = 총 코스트
              - (울슈레 획득 수 × 0.2)
              - (레전드레어 획득 수 × 2)
최종 균형 코스트 하한 = 0
```

목표를 모두 얻은 순간 경로는 종료한다. 하한 0과 같은 점수에서 더 짧은 목적지를
우선하므로 음수 보상을 쌓기 위해 불필요하게 진행하지 않는다.

예를 들어 플래티넘 또는 레전드 티켓 1회로 10A에서 끝나는 경로의 코스트는 `2`이고,
레어티켓 20회로 21A에서 끝나는 경로의 코스트는 `0.6`이다. 최단거리 모드는
전자를, 최소코스트 모드는 후자를 선택한다.

R 열변경과 일반 이벤트 전환에는 별도 비용을 붙이지 않는다. 중복 레어의 R
재추첨은 한 번의 레어티켓 행동 안에서 일어나므로 추가 `0.03`을 붙이지 않는다.

## 6. 행동 및 목표 획득 규칙

### 6.1 일반 이벤트 단뽑

- 현재 RNG 상태와 직전 획득 캐릭터를 사용해 선택 이벤트에서 한 번 뽑는다.
- 플래티넘·레전드 티켓 배너는 일반 이벤트 후보에서 반드시 제외한다. 사용자가
  그 배너를 행으로 선택해도 레어티켓 `0.03` 행동으로 사용할 수 없다.
- 같은 위치에서 선택된 모든 이벤트를 각각 계산한다. 한 이벤트에서는 중복 R이
  발생하지만 다른 이벤트에서는 다른 레어 또는 상위 희귀도가 나와 R을 피할 수
  있으면 안전한 이벤트 전환도 경로 후보로 사용한다.
- 중복 레어면 기존 게임 규칙대로 R 재추첨과 열변경을 적용한다.
- 모든 목표를 이벤트 획득으로 달성 처리할 수 있다.
- 이벤트를 바꾸더라도 직전 캐릭터 상태는 유지한다.
- 행동 1회당 코스트는 `+0.03`이다.

### 6.2 통조림 확뽑

- 실제 `guaranteed_rolls == 11`인 선택 이벤트에서만 사용할 수 있다.
- 입력한 최대 사용 횟수를 넘지 않는다.
- 10개의 일반 결과와 마지막 확정 결과 전체에서 이벤트 목표를 획득 처리한다.
- 중간 중복 레어 및 마지막 G 반 칸 진행을 기존 Gacha 규칙과 동일하게 적용한다.
- 행동 1회가 완전히 끝난 다음 위치를 경로의 도달 위치로 사용한다.
- 코스트는 1회당 `+1`이다.

### 6.3 특수 티켓

- 플래티넘과 레전드 티켓은 각각 독립된 최대 횟수와 사용량을 가진다.
- 사용한 횟수가 해당 티켓의 입력 최대 횟수보다 작을 때만 행동 후보가 된다.
- 선택 행에 해당 종류의 특수 티켓 배너가 있으면 그 정확한 풀을 사용하고,
  없으면 지역별 최신 활성 플래티넘/레전드 티켓 풀을 종류별로 사용한다.
- 일반 뽑기 한 번과 같은 두 RNG 값을 소비하지만 결과가 레어가 아니므로
  중복 레어 R 전환을 방어할 수 있다.
- 현재 또는 바로 다음 중복 레어 방어가 필요한 위치와, 그 위치의 특수 티켓
  결과가 `allow_ticket=true`인 미획득 목표인 경우에 분기 후보가 된다.
- `allow_ticket=false`인 목표는 두 특수 티켓 결과로 달성되지 않는다.
- 방어용이든 목표 획득용이든 사용 1회당 코스트는 동일하게 `+2`다.

### 6.4 지역 제한

- 한 번의 Find 계산에 참여하는 이벤트는 모두 같은 지역이어야 한다.
- KR과 JP 행이 함께 선택되어 있으면 계산 시작 전에 지역 선택 오류를 표시한다.
- 캐릭터 이름은 KR 데이터가 있으면 한국어명을 사용하고, 아직 KR에 없는 JP
  캐릭터만 JP 이름으로 대체 표시한다.

## 7. 필요한 데이터 계약

기존 `/track.json`은 이벤트 풀 데이터만 제공하고 실제 다중 이벤트 경로는
브라우저에서 계산한다. Find에 다음 데이터가 추가로 필요하다.

- 전체 KR/JP 캐릭터 중 희귀도 3, 4, 5의 간단한 카탈로그
  - ID
  - 한국어 우선 표시명
  - 희귀도
- 선택 이벤트별 기존 풀 데이터
- 지역별 특수 티켓 풀 데이터
  - 플래티넘 티켓과 레전드 티켓을 별도 항목으로 제공
  - 이벤트/풀 식별자와 적용 기간
  - 희귀도 슬롯과 캐릭터 정보

카탈로그에는 설명과 이미지를 넣지 않는다. 이름, ID, 희귀도만 내려 payload와
상류 충돌 가능성을 줄인다.

특수 티켓 결과로 목표를 획득할 수 있으므로, 단순히 `레어가 아닌 임시 캐릭터`
로 처리해서는 안 된다. 정확한 티켓 풀과 해당 RNG 결과가 필요하다.

## 8. 탐색 모델

이벤트별 표의 `.next` 링크만 조합해서는 안 된다. 배너를 바꿔도 직전 캐릭터가
유지되어 숨은 R 전환 여부가 달라지기 때문이다. Find는 다음 전역 상태를 직접
추적한다.

```text
State {
  rng_seed,
  track_position,
  last_rare_or_non_rare,
  acquired_target_mask,
  guaranteed_used,
  platinum_used,
  legend_ticket_used
}
```

총 코스트는 상태 지배 비교를 위한 정수 비용 라벨에 둔다. 같은 핵심 상태에
도달했다면 코스트가 크거나 제한 자원 사용량이 많은 경로를 버린다.

탐색은 위치별 label-setting DP로 구현하며 최종 후보 comparator는 사용자가
선택한 `최단거리`, `최소코스트`, 또는 `균형` 순서를 따른다.

성능을 위해 다음을 적용한다.

- 목표 캐릭터 등장 위치를 이벤트별로 미리 색인
- 일반 전이를 `(seed, last rare, event)` 단위로 메모이즈
- 비레어 직전 캐릭터는 중복 레어 판정 관점에서 하나의 상태로 압축
- 같은 위치에서 결과와 다음 상태가 같은 이벤트 전이는 하나로 병합
- 특수 티켓 분기는 현재/바로 다음 R 방어 지점 또는 티켓 허용 목표 획득
  지점에서만 생성
- 확뽑 분기는 실제 확정 이벤트와 남은 허용 횟수가 있을 때만 생성
- 같은 상태·획득 마스크에서는 더 큰 코스트 또는 더 많은 제한 자원 사용 경로 제거
- `count` 밖으로 나가는 행동은 생성하지 않음

목표가 많을수록 획득 마스크가 `2^N`으로 증가한다. 구현 후 실제 벤치마크를
바탕으로 경고 기준과 상태 수 안전 한도를 정한다. 안전 한도로 중단된 경우
`불가능`이 아니라 `계산 범위 초과`로 표시한다.

## 9. 비동기 실행과 결과 표시

- 기존 Track A/B 배열을 먼저 렌더링한다.
- Find 계산은 Web Worker에서 시작한다.
- 결과 영역은 Found cats와 Track A 사이에 둔다.
- 계산 중에는 `계산 중… 5s`처럼 1초마다 시간을 갱신한다.
- Seed, count, 이벤트, 목표 또는 Find 옵션이 바뀌면 이전 Worker를 종료한다.
- 완전 탐색으로 경로가 없음을 증명한 경우에만 `불가능`을 표시한다.
- 완료 결과 옆 `계획표 그리기`를 눌렀을 때만 Track 표에 발자국을 표시하며,
  같은 버튼으로 표시를 지울 수 있다.

결과는 일반 단뽑을 한 줄씩 모두 표시하지 않고 중요한 행동을 압축한다.
이벤트명은 목표 획득, R 열변경, 확뽑처럼 해당 배너를 실제로 선택해야 하는
행동에만 표시하고 단순 레어티켓 진행 구간에서는 생략한다. 비교 가능한 다른
이벤트가 R을 일으키지만 선택 경로의 이벤트가 R을 피하는 경우도 중요 행동으로
분류해 `R 방어를 위해 이 배너에서 뽑기`라고 표시한다. 선택 이벤트가 하나뿐인
경우에는 비교 기반 R 방어 문구를 표시하지 않는다.
균형 모드에서 코스트 보상으로 계산된 울슈레·레전드레어 획득도 해당 이벤트와
보상 수치를 별도 행동으로 표시해 사용자가 같은 경로를 재현할 수 있게 한다.

```text
8A · 이벤트 1075 · 아쿠아슈터 사키 획득
17A · 플래티넘 티켓 사용 · R 전환 방어 (+2)
24A~34B · 이벤트 1021 확뽑 · 명계의 칼리파 획득 (+1)
41B · 레전드 티켓 · 바람의 신・윈디 획득 (+2)

완료: 41B
레어티켓 12회 × 0.03 + 플래티넘 1회 × 2 + 레전드 티켓 1회 × 2
+ 확뽑 1회 × 1 = 총 코스트 5.36
목표 3/3
```

## 12. 기준 예시

초기 수용 fixture:

```text
seed: 3671843074
count: 500
max guaranteed: 2
events:
  - 2026-08-21_1075
  - 2026-08-24_1021
  - 2026-08-26_1043
targets:
  - 아쿠아슈터 사키
  - 명계의 칼리파
  - 바람의 신・윈디
```

현재 데이터에서 확인된 사항:

- `2026-08-21_1075`에 아쿠아슈터 사키가 있다.
- `2026-08-24_1021`에 명계의 칼리파와 바람의 신・윈디가 있다.
- 세 이벤트 모두 11연 확정 이벤트다.

이 fixture에서 확정한 최적 경로:

```text
1A~16A   레어티켓 16회                                     -> 17A
17A~17AG 2026-08-21_1075 확뽑 · 아쿠아슈터 사키 @17AG (+1) -> 27B
27B~30B  레어티켓 4회                                      -> 31B
31B~31BG 2026-08-24_1021 확뽑 · 명계의 칼리파 @35B,
           바람의 신・윈디 @31BG (+1)                       -> 42A

완료 위치: 42A
플래티넘 티켓: 0회
레전드 티켓: 0회
확뽑: 2회
총 코스트: 2.6 (레어티켓 20회 + 확뽑 2회)
목표: 3/3
탐색 상태: 212개
브라우저 Worker 탐색 시간: 약 0.01s
```

아쿠아슈터 사키를 `특수 티켓 허용`으로 바꿔도 같은 목적지에서는 이벤트 획득
경로가 비용이 더 낮으므로 위 경로가 그대로 선택된다.

추가 성능 기록:

| 조건 | 결과 | 상태 수 | 브라우저 Worker 시간 |
| --- | --- | ---: | ---: |
| 기준 예시 · 최단거리 | 42A / 코스트 2.6 | 212 | 약 0.01s |
| 기준 예시 · 최소코스트 | 62A / 코스트 2.47 | 433 | 약 0.01s |
| 기준 예시 · 균형 | 62A / 균형 코스트 0 | 3,231 | 약 0.02s |

목표가 16개 이상이면 UI에서 연산량 경고를 표시한다. 탐색 상태가 400,000개에
도달하면 `불가능`이 아니라 `계산 범위 초과`로 종료한다.

## 13. 확정된 결정

구현 전에 보류했던 항목은 다음과 같이 확정했다.

1. 선택한 캐릭터는 모두 반드시 획득해야 하는 목표다. 별도 필수 체크와 선호
   목표 개념은 두지 않는다.
2. `특수 티켓 허용` 목표는 이벤트, 플래티넘 티켓, 레전드 티켓 중 어느 쪽으로
   얻어도 달성한다. 두 특수 티켓 행동의 코스트는 각각 항상 `+2`다.
3. 검색 기준 기본값은 `최소코스트`이며 `최단거리`와 `균형`을 선택할 수 있다.
   총 코스트는 레어티켓 `0.03`, 확뽑 `1`, 플래티넘 `2`, 레전드 티켓 `2`를
   합산한다.
   균형은 울슈레 `-0.2`, 레전드 `-2`를 적용하고 최종 점수는 0 아래로 내리지
   않는다.
4. 특수 티켓 풀은 플래티넘과 레전드 티켓을 종류별로 분리한다. 사용자가 해당
   특수 배너를 행에 선택하면 그 풀을 쓰고, 그렇지 않으면 계산 시점의 지역별
   최신 활성 풀을 사용한다.
5. `Use ticket` 체크박스 대신 플래티넘과 레전드 티켓 최대 횟수를 각각 입력한다.
   두 기본값은 0이며 탐색은 각 입력 횟수를 절대 넘지 않는다.
