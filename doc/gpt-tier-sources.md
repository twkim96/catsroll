# 속성별 티어 추천의 출처와 매칭 기준

## 최종 육성 기준: Bestnyanko

- 사용자 지정 우선 출처: [Bestnyanko 시리즈별 티어표](https://fronthefrost.github.io/Bestnyanko/), 확인일 2026-11-01.
- 시리즈별 하위 HTML의 실제 `tier-row`/`t-card`만 대조한다. 숨은 검색용 이름은 평가 카드로 세지 않는다. 원본 이미지·설명은 복제하지 않는다.
- `gpt-knowledge/final-tier-picks.json`에 ID·형태·등급·출처 URL·매칭/투자 가정을 저장한다. 게임 버전·갱신일이 확인되지 않은 값은 `unknown`이며 확인일을 원문 갱신일로 바꾸지 않는다.
- 최종 육성 평가는 이 출처를 우선한다. 기존 평가가 더 높아도 고성장에는 새 등급을 그대로 사용한다. 두 출처 중 높은 값만 고르지 않는다. 각 표 내부의 상대 평가이며 다른 시리즈의 동급을 절대 동급으로 취급하지 않는다.
- 기존 `tier-picks.json`은 수정·삭제하지 않고 형태/투자 조건별 이전 평가로 보존한다. 저성장(`investment=none/talents`)에는 기존 평가만, 고성장(`investment=ultra`)에는 새 평가만 사용한다. 고성장에서 새 평가가 미등록/형태 제한으로 제외되면 이전 고성장 값으로 보충하지 않는다. 원문에 해당 조건의 평가가 없으면 새 평가를 역산하지 않는다.
- 기본 추천은 4진·초본능까지의 잠재력 비교다. 계정의 현재 해금 상태·재료·NP 예산을 알고 있다는 뜻이 아니다. 원문은 티어별 필수 본능/초본능을 명시하지 않으므로 게임 데이터의 사용 가능한 강화를 기준으로 둔 연동 가정을 `evaluation_assumptions`와 함께 밝힌다.
- 기존 캐릭터 설명은 평가 형태와 투자 조건이 맞는 경우에만 `source_notes`로 연결한다. 다른 형태의 설명은 `other_form_notes`로 구분하고, 원문에 없는 최종 티어의 이유를 만들어내지 않는다.
- 원본 카드 294개 중 291개는 일반 가챠 추천에 연결했다. 선물 성격의 쿠니오군(625)·리키(722)·류이치&류지(875) 3개는 ID/형태만 확인되어 `reference_ratings`로 상세 조회에 제공하고 일반 풀 추천에는 넣지 않는다. 지역별 미출시 형태/캐릭터는 해당 지역 추천에서 제외하며 이전 고성장 값으로 대체하지 않는다.
- 현재 표기와 ID/형태·소속의 매칭이 확인되지 않은 카드는 `unresolved_evaluations`로 보존하며 기본 D를 부여하지 않는다. 범례에 없는 새 시리즈 간 순위도 만들지 않는다.

## 데이터의 소유

`gpt-knowledge/tier-picks.json`은 `cat_id`, 원문 시리즈 ID, 평가 등급, 평가 형태,
본능/초본능 조건과 이미지 순번만 보관한다. 원문 그림·설명 문장을 복제하지 않는다.
캐릭터 이름·진화형·대상 속성·능력·본능 효과는 Catsroll의 기존 `Route.ball_kr/jp.cats`,
`Stat`, `Ability`, `Talent`에서 읽는다. 이름이나 속성을 티어 파일에 별도로 유지하지 않는다.

예: 원문 ‘헬옹마’는 사이트의 ID 45 ‘도깨비 야옹마’, 원문 ‘백포노’는 ID 691
‘운명의 아이 포노’, 원문 ‘산디아’는 ID 77 ‘번개의 신・산디아’에 연결한다.
ID에 매칭한 뒤 응답은 현재 사이트의 기본 이름과 평가 형태 이름을 사용한다.
원문 표기의 ‘가이아’와 사이트의 ‘가이야’ 같은 차이도 이름만으로 다른 캐릭터를 만들지 않는다.

## 그림 해석의 경계

등급은 초상화의 배치와 하단 등급 띠를 함께 확인했다. 보라 테두리는 레전드 표시이며
SS라는 뜻이 아니다. 강화 초상화 화살표는 4단 진화 또는 초본능일 수 있으므로,
공식 데이터의 형태와 본능 정보를 함께 확인했다. 보라 글씨만으로 초본능이라고 판단하지 않는다.

- 초상화가 등급 경계에 걸치면 `SS/S`, `S/A`, `A/B`, `B/C`, `C/D`처럼 범위를 보존한다.
  단일 등급을 만들어내지 않으며 추천 정렬에서만 하한을 사용한다.
- 4진이 필요한 강화 평가는 form 4 조건으로 분리한다. 초본능 강화와 혼동하지 않는다.
- 강화 투자의 범위가 원문과 현재 데이터로 대조되지 않으면 조건을 명시하거나 미확정으로 둔다.
  데이터에 없는 본능·형태를 대신 적용하지 않는다.
- 기존 데이터에 해당 형태/강화가 없으면 `unresolved_evaluations`에 근거를 보존하고 추천 계산에서 제외한다. 개별 조회의 `pending_evaluations`로 확인할 수 있다.

## 조회와 정렬

전체 평가를 저장해도 매번 전부 전달하지 않는다. `catsroll_recommend`는 기존 기본 5종·최대 10종을
유지하고 `total_candidates`/`returned_count`와 `dataset_coverage`를 구별한다. 추천 목록을
배너의 전체 평가표로 설명하지 않는다. 특정 캐릭터는 `catsroll_cats(details=true)`의
`source_ratings`로 낮은 등급·강화 전후 평가를 모두 조회한다. 데이터에 없는 것은 평가 없음이며
D등급이 아니다. 추가 자료의 `source_notes`는 역할·투자·수집 의견으로 유지하고 임의로 등급에 환산하지 않는다.

`catsroll_recommend`는 요청 속성을 평가 형태의 실제 대상 속성과 대조한다.
일반 본능 평가는 일반 본능만, 초본능 평가는 초본능까지 적용해 대상 추가를 반영한다.
기본 예산은 일반 본능까지이며 4진/초본능은 명시적 ultra 예산이 필요하다.
같은 캐릭터의 여러 평가 형태가 있으면 조건에 맞는 최상위 형태 하나만 남긴다.
순서는 SS→S→A→B→C→D이며 범위는 하한으로 정렬한다. 같은 등급에서는 요청 속성 일치/대상 폭과 투자 조건 등을
재현 가능한 보조 기준으로 사용한다. 대상 속성 개수는 절대 성능 점수가 아니다.

기믹 대처는 속성 포함만으로 보장하지 않는다. 메탈의 크리티컬, 좀비 킬러, 악마 쉴드
브레이커 등은 별도 능력을 확인해야 한다. 사용자의 보유·육성·진행 상황도 자동으로 알지 못한다.
현재 기계 필터는 대상 속성과 투자·보유·배너 풀을 다루며 전투 시뮬레이션은 하지 않는다.

## 이번 확장의 검사 범위

추천·카탈로그·가이드·양쪽 호스트 공개 계약의 기존 회귀를 실행했다. 낮은 등급과 범위 정렬,
동일 캐릭터의 강화 전후 평가, 존재하지 않는 본능 배제, 다군의 실제 울슈레 풀을 5종씩
끝까지 조회해 모든 캐릭터에 평가가 연결되는지를 포함한다. 계약 비교의 Claude 접두어
차이는 호스트별 설명 변경만 허용한 `tier_coverage_delta_v1.json`으로 명시했고 해당 검사를 재통과했다.

알 수 없는 배너나 사용할 수 없는 풀은 필터를 완화하지 않고 오류로 처리한다.

이 서버 검증은 캐릭터 메타데이터와 획득 풀의 검증이다. 주관적인 성능 티어의 참/거짓을
서버가 증명하는 것이 아니다. 실제 뽑기 가능 시기와 시드별 획득 경로는
`catsroll_events`와 계산 앱의 Find 결과로 별도 확인한다.

자동으로 따라가지만, 변경된 능력으로 인해 과거 평가가 유효한지는 다시 판단해야 한다.
출처 버전·날짜를 지우지 않는다. 무료 ChatGPT에서 실제 추천 도구가 선택되는지는 별도 수용 조건이다.
