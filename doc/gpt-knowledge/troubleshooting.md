# 예상과 다르거나 지원 범위가 헷갈릴 때

## 실제 뽑기와 다릅니다

추가 뽑기를 권하기 전에 현재 시드, 관측 시작/현재 시드 구분, 지역, 실제 배너 날짜, 직전 캐릭터,
일반/확정/특수 티켓 종류, 사이에 다른 뽑기를 했는지 순서대로 확인한다.
배너 이름만 같고 풀이 다르거나 미래 울슈레를 중복 추가했는지도 확인한다.
후보가 여러 개인 시드를 정답으로 고른 적이 있다면 다시 검증해야 한다.
기기 변경·복구·업데이트를 했다는 사실만으로 시드가 초기화됐다고 단정하지 않는다.
실제 불일치 원인을 확인하고, 입력을 바로잡아도 맞지 않으면 지원하는 연속 일반 관측으로 다시 찾는다.

## 이미 게임에서 뽑았어요

앱은 게임을 읽지 않으며 실제 뽑기·진행 기록을 자동 저장하지 않는다.
게임은 자동 진행되지 않는다. 현재 공통 Multi의 결과 이름 클릭은 플랜 모드가 꺼진 경우
사이트/앱의 시드·직전 결과를 갱신하는 시뮬레이션이다. 실제로 뽑은 결과와 일치하는지 확인한다.
과거 시드를 그대로 넣어 다음 결과라고 답하지 않는다. 현재 시드를 확인하거나, 지원되는 연속 일반 관측으로 시드 찾기를 다시 안내한다.
기존 사이트 Multi의 진행·공유·PNG 기능이 MCP 앱에 모두 들어 있다고 약속하지 않는다.

## 냥티·럭티·이벤트 뽑기도 되나요?

현재 MCP의 검증 범위는 레어 뽑기 계열과 지원하는 특수 티켓 배열이다.
냥코 티켓·럭키/G 티켓·아이템 이벤트 뽑기·닼캣아 파밍과 이들 사이의 중복 조작은 이 안내로 검증하지 않았다.
일반 레어/플티와 같은 시드나 전환 규칙으로 계산해 주지 않는다. 냥티를 레티로 오인하지 않는다.
스텝업 구매 단계 전체를 관측 기록으로 해석하는 기능도 없다.

## 앱이 안 열리거나 결과를 못 읽을 때

앱의 다시 시도를 안내하고, 계속 실패하면 `catsroll_site_link`로 iframe 없는 일반 배열/Multi/독립 앱 링크를 제공한다.
입력과 링크별 생략/미지원 조건은 `website` 안내를 따른다. iframe 실패여도 MCP 배너 검색은 가능할 수 있다.
MCP 자체가 실패하면 고정 사이트 주소와 수동 입력 순서를 안내하고 event ID를 만들지 않는다.
사용자가 계산한 뒤 결과 공유를 눌러야 GPT가 그 요약을 볼 수 있다. 화면을 볼 수 없으면 결과를 봤다고 말하지 않는다.
공유 요약에서 생략된 행·경로를 상상해서 채우지 않는다. 준비 데이터만 있으면 “계산 전”이라고 설명한다.
현재 시험 버전에는 ChatGPT 첫 표시/답변 표시 문제와 무료 계정 수용 검증이 남아 있다.

## 계산·보관·전달·추가 조회 실패

계산 결과와 공유 상태를 먼저 구분하고 실패한 단계만 복구한다. 공유가 끝난 뒤 모든 오류를 앱 첫 진입 실패로 취급하지 않는다.

| 확인한 상태 | 다음 행동 |
| --- | --- |
| iframe만 미표시 | 연결·목록 재시도. 계속 실패하면 알려진 입력으로 `catsroll_site_link`를 호출한다. 카탈로그 실패라고 단정하지 않는다. |
| MCP 전체 불가 | 고정 사이트와 수동 입력을 안내한다. ID·인코딩 링크를 만들지 않는다. |
| 기기 계산 중단·실패 | 입력을 보존하고 해당 계산 오류·재시도를 확인한다. 자동 서버 계산으로 바꾸지 않는다. |
| 저장 실패·메시지 전달 성공 | 직접 전달된 내용만 설명하고 전체 상세가 보관되지 않았음을 밝힌다. |
| 저장 성공·메시지 전달 실패 | 같은 고정 캡처를 다시 전달하거나 복사/JSON 내보내기로 공유한다. 재계산하거나 새 입력과 섞지 않는다. |
| 공유 성공·result 도구 없음/미공개 | 이미 받은 요약·배열은 사용할 수 있다. 추가 조회만 불가하며 없는 상세만 같은 캡처에서 내보내도록 안내한다. |
| ID 만료·서버 재시작 | 대화에 남은 정보로 답하고 누락 상세만 다시 공유받는다. 같은 시드로 원 스냅샷을 복구했다고 말하지 않는다. |
| 모델 답변 표시 오류 | 계산·보관·전달 상태와 분리해 확인한다. 계산 지연이 원인이라고 단정하지 않는다. |

결과를 추가로 읽는 절차와 생략/페이지 한계는 `find`의 ‘결과 상세 조회와 페이지 커서’와 ‘결과 필드·총 뽑기 수·생략 범위’를 따른다. 이 안내는 일반 배열 공유에도 적용된다.

관련 문서: `seed`, `banners`, `find`.
