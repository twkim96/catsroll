# 확정 뽑기, G/RG와 시뮬레이션

## 짧은 답

`G`는 그 자리에서 확정 묶음 뽑기를 시작할 때 마지막에 받는 확정 울슈레다.
`RG`는 시작 결과에 레어 중복 재추첨이 적용된 경우의 확정 결과다. 같은 칸의 일반 이름과 G를 둘 다 한 번의 단뽑 결과라고 읽지 않는다.
R/G/RG는 표기이며, 게임에서 확정 뽑기를 사용할 수 있다는 보증이 아니다.

## 다음 위치

일반적인 11회 확정 묶음은 일반 결과 10개와 마지막 확정 울슈레 1개를 계산한다.
중간 중복 레어가 있으면 이동 경로가 달라질 수 있다. “11회면 항상 11B”라고 말하지 않는다.
앱이 보여 주는 확정 결과와 다음 위치를 함께 확인한다. 11회 일반 연속 뽑기를 확정 묶음으로 입력하지 않는다.

## 설정의 의미

- `forceGuaranteed=0`: 선택한 배너 데이터의 기본값을 사용한다. 무조건 확정 없음이라는 뜻은 아니다.
- `2`, `7`, `11`, `15`: 기존 Multi 엔진이 지원하는 확정 묶음 길이 가정이다.
- 2·7·15를 고를 수 있어도 현재 게임 상품이나 스텝업 단계의 제공 여부는 별도다. 단계별 구매 이력을 입력받는 기능은 없다.
- 현재 일정이 확정인지 확인하지 못했다면 시뮬레이션이라고 밝힌다. 사용자의 “확뽑 가능” 동의 없이 실제 추천 경로에 넣지 않는다.

## 물을 것과 도구

“11회 확정을 사용할 수 있나요? 최대 몇 번까지 사용할까요?”를 필요한 경우 묻는다.
`find`의 `maxGuaranteed`는 허용할 확정 묶음 사용 횟수다. 0이면 허용하지 않는다.
배너가 여러 날짜로 나뉘면 실제 확정 기간의 배너를 `catsroll_events`로 확인한다.
일반 뽑기 관측만 받는 현재 시드 찾기에 확정·스텝업 결과를 섞지 않는다.

관련 문서: `tracks`, `banners`, `find`.
