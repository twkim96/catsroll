# 실제 사이트 사용법과 스크린샷 상담

앱 카드가 열리지 않아도 배너·캐릭터 조회 도구는 별도로 동작할 수 있다. 계산 화면 표시 실패와 MCP 서버 연결 실패를 구분한다.
이 안내는 현재 Catsroll 코드에 맞춘 사용법이다. 다른 배열 사이트의 버튼 이름·색상·진행 방식을 그대로 적용하지 않는다.

## 사이트로 이어주기

- [일반 배열](https://twkim96-my-cats-rolls.hf.space/?compute=client): 배너 하나의 A/B·R/G/RG를 본다.
- [Multi 배열](https://twkim96-my-cats-rolls.hf.space/multi): 여러 배너 비교, Find, 플랜, 공유를 사용한다.
- [독립 계산 앱](https://twkim96-my-cats-rolls.hf.space/gpt): 채팅 iframe 밖에서 앱을 연다. 시드 찾기와 모든 준비 조건 복원에 사용한다.

1. 사용자가 말한 지역·현재 시드·배너/날짜·횟수·직전 결과를 유지한다. 배너 ID를 모르면 `catsroll_events`로 찾는다. 목표가 없는 배열 열기에 캐릭터를 요구하지 않는다.
2. **`catsroll_site_link`**에 `catsroll_prepare`와 같은 입력을 전달한다. iframe을 열지 않고 텍스트 링크를 반환한다. 기본 100회·최대 300회이며 명시한 횟수는 유지한다. 이 도구는 계산하지 않는다.
3. `websiteLinks.multi`는 여러 배너와 활성 Find 조건을 전달한다. 기존 설정을 덮어쓰지 않는 편집 가능한 공유 세션이다. 웹을 열면 기기에서 배열/활성 Find를 계산한다. 플랜 이름·활성화·도장/경로는 옮기지 않으므로 필요한 경우 사용자가 플랜을 다시 만든다.
4. `websiteLinks.tracks`는 배너별 일반 배열 링크다. 지역·배너·시드·last·횟수·미래 울슈레·강제 확정을 포함하고 `compute=client`를 유지한다. 다른 배너·Find 목표/예산/일정·플랜은 포함하지 않는다. 목표 경로 전체를 옮긴 링크라고 설명하지 않는다.
5. `websiteLinks.app`과 기존 `siteUrl`은 준비 입력 전체를 보존하는 독립 앱이다. 시드 찾기, 참고 풀 `previewFor`, 일반 웹 한도를 넘는 미래 울슈레·웹 Find 선택기에 없는 목표 등은 이쪽을 쓴다. 계산 버튼을 직접 누른다. `unavailable`이 있으면 이유를 알리고 조건을 몰래 줄이지 않는다.
6. 일반/Multi 사이트 결과가 채팅에 자동 전달된다고 약속하지 않는다. 화면 캡처·공유 링크·Find 경로 텍스트로 상담할 수 있다. 전체 구조화 결과 공유/조회가 필요하면 독립 앱의 결과 공유·복사/JSON 내보내기 흐름을 사용한다.

MCP 자체가 끊겼다면 위 고정 사이트 링크와 수동 입력 순서를 안내한다. 배너를 조회하지 못했다고 배너가 없다고 단정하거나 event ID를 지어내지 않는다. 같은 서버의 사이트도 접속되지 않을 수 있으므로 정상 대체 접속을 보장하지 않는다.
링크는 비밀번호가 아니며 복호화 가능한 입력을 담는다. 일반 배열 링크의 query는 사이트 요청에 포함되고, Multi/독립 앱의 fragment도 링크를 받은 사람이 읽을 수 있다. 개인 입력을 공개 게시하라고 요구하지 않는다.

## 일반 배열: 입력부터 실제 진행까지

1. **Region**에서 게임 지역을 선택하고 **Event**에서 실제 뽑을 기간의 배너를 선택한다. 배너 필터는 목록을 좁히는 기능이며 레어 풀을 섞는 기능이 아니다.
2. **Seed**에 현재 시드, **Count**에 표시 행 수를 넣고 **Roll**을 누른다. **Last roll**은 바로 직전 결과다. 첫 1A의 중복 판정에 영향을 주므로 아는 경우에만 정확히 넣는다.
3. **Find next**는 그 캐릭터 위치를 찾고 강조하는 기능이다. Multi Find처럼 여러 배너·자원 한도로 전체 획득 경로를 최적화하지 않는다.
4. **Simulate guaranteed**는 확정 묶음 길이를 가정한다. 빈값/0은 배너 기본 조건이고, **Exclude guaranteed**는 Find next의 확정 후보를 제외하는 옵션이다. 게임에서 실제 확정이 제공된다는 보증이 아니다.
5. **Add future ubers**는 가상의 신캐 수다. 이미 해당 신캐가 들어간 새 배너에 중복 추가하지 않는다. **내 기기 연산**은 계산 위치를 정한다. 링크 도구는 client로 연다. 자동으로 서버 연산으로 바꾸지 않는다.
6. A/B는 가능한 경로다. 다음 행동은 현재 위치의 일반/R 또는 G/RG 옆 **다음 좌표**로 확인한다. 발바닥은 캐릭터 정보 링크다. 일반 이름은 단뽑 진행, 확정 결과 이름은 그 위치에서 묶음 진행에 해당하므로 클릭한 종류를 구분한다.
7. 실제로 뽑은 결과에 맞는 이름을 눌러 사이트의 시드/직전 결과를 갱신한다. 클릭 자체가 게임 뽑기를 실행하지 않는다. 잘못 누르면 뒤로 가거나 최근 시드에서 되돌린 뒤 확인한다.

## Multi: 배너 비교·Find·플랜

1. Seed·Count·Last를 넣고 배너 행마다 지역·기간을 고른다. `+`는 배너 추가, 휴지통은 해당 행 삭제, 깔때기는 시리즈 필터다. 배너를 추가해도 뽑기 횟수가 배너별로 새로 생기지 않는다. 한 시드 상태를 각 풀에 대입한 비교다.
2. **F/U**는 미래 울슈레 수, **S/G**는 확정 묶음 가정이다. 배너 행별로 설정한다. **Custom name**을 고쳐도 실제 풀은 바뀌지 않는다. 입력을 바꾼 후 **Apply**로 다시 계산한다.
3. **Found cats**는 현재 표시 범위에서 찾은 캐릭터와 위치를 펼쳐 보는 목록이다. A/B의 모든 결과를 실제로 모두 획득했다는 뜻이 아니다.
4. Find는 캐릭터 필터에서 목표와 특수 티켓 획득 허용을 고르고, 검색 기준·확뽑/플래티넘/레전드 최대 횟수를 지정한 뒤 Apply한다. 최대 횟수는 예산이며 확정 개최나 티켓 획득 허용과 다르다. `?`에서 기준을 확인한다. 일정 순서를 고려할지도 확인한다.
5. 결과의 시작 위치·배너·일반/확정/특수티켓 행동·다음 좌표를 순서대로 읽는다. 비용은 엔진 비교 가중치다. success/partial/limit/impossible을 구별하고 경로가 없다고 영원히 불가능하다고 말하지 않는다.
6. 플랜 모드를 켜면 도장을 찍어 경로를 편집하고 그리기 실행·저장/불러오기를 사용한다. 도장은 실제 뽑기 기록이 아니며 플랜 모드를 끄면 기본 배열 편집으로 돌아간다. 플랜 중 클릭을 일반 시드 이동으로 설명하지 않는다.
7. 플랜 모드가 꺼진 일반 웹 Multi에서 캐릭터 이름을 누르면 선택한 결과 뒤의 시드·last로 배열 전체가 갱신된다. 일반 배열과 마찬가지로 진행 후 시작 위치는 다시 1A 기준이 된다. 기존 8B가 새 화면 1A가 되는 것과 게임에서 열이 바뀌지 않았다는 것은 다르다.
8. 공유의 **공유하기**는 편집 가능한 입력/플랜 링크, **PNG 저장/복사**는 정적인 그림이다. 그림만으로 생략된 다른 배너·이전 행동을 복원할 수는 없다. 공유 세션의 편집은 기존 저장 설정과 분리된다.

## 스크린샷으로 “열 넘어가?”를 상담하는 순서

사용자가 제공한 화면을 직접 읽고, 보이는 사실과 조건부 추론을 구분한다. 먼저 2~4문장으로 답하고 빠진 핵심 1~2개만 묻는다. JSON/숫자 ID를 사용자에게 요구하지 않는다.

1. **어떤 화면인지**: 일반 웹, Multi, 독립/MCP 앱, 타 사이트인지 구분한다. 플랜 모드/Find 도장, 시드 갱신 전후도 확인한다.
2. **현재 위치와 행동**: 지금 뽑을 칸인지 이미 먹은 칸인지, 일반 단뽑·비확정 연뽑·확정 묶음·특수 티켓 중 무엇인지 확인한다. “7A까지 먹었다”는 7A가 다음 시작이라는 뜻이 아니다.
3. **해당 결과와 다음 좌표**: 기본 이름/R/G/RG 중 실제 조건에 맞는 줄을 읽는다. `→ 8B`가 선명하면 그 행동 뒤의 다음은 8B다. 조건부 줄이면 그 줄의 선행 배너·직전 결과도 확인한다. 색·울슈레 이름·화살표 방향만으로 보이지 않는 좌표를 추측하지 않는다.
4. **중복 레어**: 바로 직전 결과와 이번 레어가 같아야 재추첨 조건이 된다. 같은 이름이 세로로 보이는 것만으로 실제 연속 중복을 확정하지 않는다. 배너 변경으로 레어가 달라지거나 중간에 다른 희귀도/특수 티켓이 끼면 R 경로가 달라질 수 있다.
5. **확정과 중복을 함께 확인**: 확정 묶음도 중간 레어 중복에 따라 다음 열/행이 달라진다. 전환이 한 번이면 다른 열, 두 번이면 같은 열로 보일 수 있다. 횟수로 직접 좌표를 더하지 말고 실제 G/RG의 다음 위치를 읽는다. 일반 11연은 확정 11연과 다르다.
6. **그림만으로 부족하면**: 직전 실제 결과, 현재 칸/눌렀던 일반·G 줄과 다음 화살표, 시드/배너/설정이 보이는 부분 중 필요한 것만 요청한다. 공략의 예시 좌표나 다른 사용자의 시드를 재사용하지 않는다. 계산 결과가 공유됐다면 catsroll_result로 해당 구간/경로를 조회한다. 미공유 웹 링크/스크린샷은 저장 결과 ID가 아니다.

### 짧은 상담 예시

- **“7A까지 먹고 확뽑하면 8B 시작해서 18B 맞아?”** → “먼저 7A에서 뽑은 뒤 다음 좌표가 8A인지 8B인지 봐야 해요. 그 다음 시작 칸의 G/RG 줄이 확정 결과와 묶음 종료 뒤 위치를 알려 줍니다.” 스크린샷에 다음 좌표가 없으면 8B/18B를 확정하지 않는다.
- **“확뽑했는데 왜 A에 그대로야?”** → 확정 제공/실제 사용, 중간 중복 레어, 누른 일반/G/RG 링크, 진행 후 1A로 재기준화됐는지 순서대로 확인한다. “확정이면 무조건 반대 열”이라고 답하지 않는다.
- **“같은 레어 두 개인데 안 넘어가”** → 이번 실제 레어와 바로 직전 결과가 같은지 확인한다. 다른 배너·티켓을 거친 경우 기존 표의 R은 조건이 달라질 수 있다. first 1A라면 Last roll도 확인한다.
- **“플티로 열 변경을 막아?”** → 티켓 자체도 진행을 소비한다. 중복이 발생할 행동 전인지 후인지 확인하고, 그 위치에서 티켓 사용 뒤 일반 풀 결과/다음 위치를 계산해 비교한다. 언제 끼워도 같은 효과라고 하지 않는다.
- **“B열 클릭했는데 이 캐릭터 나와?”** → 클릭은 사이트 시드 이동/시뮬레이션이다. 현재 위치에서 B열로 가는 실제 중복·확정 경로가 있어야 한다. 플랜 도장을 찍은 것만으로 게임에서 이동하지 않는다.

관련 문서: `tracks`, `guaranteed`, `banners`, `find`, `troubleshooting`.
