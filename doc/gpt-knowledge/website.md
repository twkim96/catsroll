# 실제 사이트 사용법과 스크린샷 상담

앱 카드가 열리지 않아도 배너·캐릭터 조회 도구는 별도로 동작할 수 있다. 계산 화면 표시 실패와 MCP 서버 연결 실패를 구분한다.
이 안내는 현재 Catsroll 코드에 맞춘 사용법이다. 다른 배열 사이트의 버튼 이름·색상·진행 방식을 그대로 적용하지 않는다.

## 사이트로 이어주기

- [일반 배열](https://twkim96-my-cats-rolls.hf.space/?compute=client): 배너 하나의 A/B·R/G/RG를 본다.
- [Multi 배열](https://twkim96-my-cats-rolls.hf.space/multi): 여러 배너 비교, Find, 플랜, 공유를 사용한다.
- [독립 계산 앱](https://twkim96-my-cats-rolls.hf.space/gpt): 채팅 iframe 밖에서 앱을 연다. 시드 찾기와 모든 준비 조건 복원에 사용한다.

1. 사용자가 말한 지역·현재 시드·배너/날짜·횟수·직전 결과를 유지한다. 배너 ID를 모르면 `catsroll_events`로 찾는다. 목표가 없는 배열 열기에 캐릭터를 요구하지 않는다.
2. **`catsroll_site_link`**에 `catsroll_prepare`와 같은 입력을 전달한다. iframe을 열지 않고 텍스트 링크를 반환한다. 기본 100행·최대 300행을 표시·탐색하며, 명시한 행 범위는 유지한다. 행 수는 실제 뽑기 수가 아니다. 이 도구는 계산하지 않는다.
3. `websiteLinks.multi`는 여러 배너와 활성 Find 조건을 전달한다. 기존 설정을 덮어쓰지 않는 편집 가능한 공유 세션이다. 웹을 열면 기기에서 배열/활성 Find를 계산한다. 플랜 이름·활성화·도장/경로는 옮기지 않으므로 필요한 경우 사용자가 플랜을 다시 만든다.
4. `websiteLinks.tracks`는 배너별 일반 배열 링크다. 지역·배너·시드·last·표시 행 수·미래 울슈레·강제 확정을 포함하고 `compute=client`를 유지한다. 행 수는 실제 뽑기 수가 아니다. 다른 배너·Find 목표/예산/일정·플랜은 포함하지 않는다. 목표 경로 전체를 옮긴 링크라고 설명하지 않는다.
5. `websiteLinks.app`과 기존 `siteUrl`은 준비 입력 전체를 보존하는 독립 앱이다. 시드 찾기, 참고 풀 `previewFor`, 일반 웹 한도를 넘는 미래 울슈레·웹 Find 선택기에 없는 목표 등은 이쪽을 쓴다. 계산 버튼을 직접 누른다. `unavailable`이 있으면 이유를 알리고 조건을 몰래 줄이지 않는다.
6. 일반/Multi 사이트 결과가 채팅에 자동 전달된다고 약속하지 않는다. 화면 캡처·공유 링크·Find 경로 텍스트로 상담할 수 있다. 전체 구조화 결과 공유/조회가 필요하면 독립 앱의 결과 공유·복사/JSON 내보내기 흐름을 사용한다.

MCP 자체가 끊겼다면 위 고정 사이트 링크와 수동 입력 순서를 안내한다. 배너를 조회하지 못했다고 배너가 없다고 단정하거나 event ID를 지어내지 않는다. 같은 서버의 사이트도 접속되지 않을 수 있으므로 정상 대체 접속을 보장하지 않는다.
링크는 비밀번호가 아니며 복호화 가능한 입력을 담는다. 일반 배열 링크의 query는 사이트 요청에 포함되고, Multi/독립 앱의 fragment도 링크를 받은 사람이 읽을 수 있다. 개인 입력을 공개 게시하라고 요구하지 않는다.

## 일반 배열: 입력부터 실제 진행까지

1. **Region**에서 게임 지역을 선택하고 **Event**에서 실제 뽑을 기간의 배너를 선택한다. 배너 필터는 목록을 좁히는 기능이며 레어 풀을 섞는 기능이 아니다.
2. **Seed**에 현재 시드, **Count**에 표시 행 수를 넣고 **Roll**을 누른다. **Last roll**은 바로 직전 결과다. 첫 1A의 중복 판정에 영향을 주므로 아는 경우에만 정확히 넣는다.
3. **Find next**는 그 캐릭터 위치를 찾고 강조하는 기능이다. Multi Find처럼 여러 배너·자원 한도로 전체 획득 경로를 최적화하지 않는다.
4. **Simulate guaranteed**는 확정 묶음 길이를 가정한다. 빈값/0은 배너 기본 조건이고, **Exclude guaranteed**는 Find next의 확정 후보를 제외하는 옵션이다. 게임에서 실제 확정이 제공된다는 보증이 아니다.
5. **Add future ubers**는 가상의 신캐 수다. 이미 해당 신캐가 들어간 새 배너에 중복 추가하지 않는다. **내 기기 연산**은 계산 위치를 정한다. 링크 도구는 client로 연다. 자동으로 서버 연산으로 바꾸지 않는다.
6. A/B는 가능한 경로다. 다음 행동은 현재 위치의 일반/R 또는 G/RG 옆 **다음 좌표**로 확인한다. 발바닥은 캐릭터 정보 링크다. 일반 이름은 단뽑 진행, 확정 결과 이름은 그 위치에서 묶음 진행에 해당하므로 클릭한 종류를 구분한다.
7. 실제로 뽑은 결과에 맞는 이름을 눌러 사이트의 시드/직전 결과를 갱신한다. 클릭 자체가 게임 뽑기를 실행하지 않는다. 잘못 누르면 뒤로 가거나 최근 시드에서 시드·Last 쌍을 되돌린 뒤 확인한다. 예전 기록의 Last가 미확인이면 직전 결과를 직접 확인해야 한다.

## Multi: 배너 비교·Find·플랜

Seed·Count·Last와 비교할 배너를 설정하고 Apply한다. 필요하면 Find 목표·허용 자원을 정해
경로를 계산하고, 플랜으로 편집·저장하거나 공유한다. 각 조작의 조건은 아래 항목을 따른다.
비용은 엔진 비교 가중치이며 게임 재화가 아니다. success/partial/limit/impossible을 구별하고,
경로가 없다고 영원히 불가능하다고 말하지 않는다.

## Seed / Count / Last roll / Apply

현재 시드·표시 행 수·직전 결과를 입력하고 적용한다. Count는 배열에서 표시·탐색할 행 범위다. 일반 웹 최대 999행과 MCP 링크 기본 100행·최대 300행을 구별한다. 실제 경로의 총 뽑기 수는 계산 결과의 `totalDraws`로 확인한다.

## 배너 추가·삭제·시리즈 필터·Custom name

`+`는 배너 추가, 휴지통은 해당 행 삭제다. 배너를 추가해도 뽑기 횟수가 배너별로 새로 생기지 않는다.
한 시드 상태를 각 풀에 대입한 비교다. Custom name을 고쳐도 실제 풀은 바뀌지 않는다.
배너 행의 깔때기는 그 행의 Event 목록을 시리즈로 좁힌다. Find 목표 선택 깔때기와 다르다. 풀의 캐릭터를 삭제하거나 여러 배너 풀을 합치지 않는다.

## F/U

그 배너에 가상의 미래 울슈레를 추가하는 수다. Multi 웹의 F/U는 0~20, 일반 배열 페이지의 미래 울슈레는 0~9다. 이미 추가된 신캐를 다시 넣지 않는다.

## S/G

0/빈값은 배너 기본 확정 조건, 2·7·11·15는 그 길이의 확정 묶음 가정이다. **확뽑 최대**는 그 묶음을 경로에서 몇 번까지 쓸지 정하는 별도 한도다. 예: S/G=11, 확뽑 최대=1은 11연 확정 묶음을 최대 한 번 허용한다. 실제 개최를 보장하지 않는다.

## 달력 아이콘

Find의 **배너 일정 순서 고려**를 켜고 끈다. 기본 OFF. 자세한 일정 규칙과 여섯 검색 기준은 `find` 안내를 읽는다. 배너를 보여주는 단순 달력 창이나 날짜 선택기가 아니다.

## 목표 선택 깔때기·선택한 캐릭터

캐릭터를 Find 목표로 고른다. 목표마다 **특수 티켓 허용**은 기본 OFF이며, 플래티넘/레전드 최대 횟수와 별도다. 양수 예산만으로 목표의 티켓 획득을 허용한 것으로 읽지 않는다.

## 목표 그룹의 올컬렉 / 초기화

올컬렉은 그 그룹의 캐릭터 전체 선택이고 보유자를 자동 제외하지 않는다. 초기화는 해당 선택을 비운다. Find 계산은 목표 최대 30종이며 초과하면 줄여야 한다. MCP의 `excludeOwnedIds`는 명시한 보유 ID를 제외하는 별도 준비 기능이다.

## 검색 기준 / ?

최소코스트·최소코스트(40)/(50)·최단거리·탐욕·파레토를 고르고 `?`로 설명을 연다. 점수/차이는 `find` 안내에 있다.

## Found cats

목록을 펼쳐 캐릭터와 위치를 확인한다. 표시된 배열 범위의 캐릭터별 좌표다. 실제 보유 목록이나 모든 A/B 결과를 동시에 얻는 경로가 아니다.

## 플랜 모드 / 그리기 실행

플랜 ON에서 클릭은 도장/행동 선택이다. 플랜 OFF의 결과 이름 클릭은 선택한 결과 뒤로 시드와 Last를 갱신한다. 그리기 실행을 게임 뽑기 실행으로 설명하지 않는다.

## 플랜명 / 저장 / 불러오기 / 초기화

일반 웹은 브라우저에 플랜을 저장·불러오며, 앱은 해당 앱 세션 동안 유지한다. 플랜 초기화는 현재 플랜명·도장을 비우며 저장 라이브러리 삭제와 다르다. 저장본 삭제는 불러오기 목록의 별도 삭제 동작이다.

## 선택 레어·슈레·울슈레·레레

플랜에서 표시할 캐릭터를 고르는 항목이다. Find의 획득 목표/특수 티켓 허용과 혼동하지 않는다.

## 공유 / PNG 저장·복사

편집 가능한 공유 링크와 정적인 이미지 내보내기를 구별한다. 링크는 현재 입력·Find·플랜 상태를 옮기며 저장된 플랜 라이브러리 전체를 내보내는 기능은 아니다. 웹 표는 채팅에 자동 공유되지 않는다.
공유 세션의 편집은 기존 저장 설정과 분리된다.

버튼이 안 보이면 사용 중인 화면(일반 배열/Multi/MCP 앱), 플랜 ON 여부와 캡처 범위를 먼저 확인한다.
일반 배열의 Roll/Find next, Multi의 Apply/Find, 독립 앱의 계산하기를 같은 버튼으로 설명하지 않는다.

## 스크린샷으로 “열 넘어가?”를 상담하는 순서

사용자가 제공한 스크린샷, 계산표, 계산된 경로 텍스트는 보이는 범위에서 유효한 근거다. `prepared` 응답은 계산 결과가 아니다. 현재 칸·실제 행동·직전 결과·다음 좌표가 화면이나 사용자의 설명에 확인되면 결과와 다음 위치를 바로 답하고, 빠진 핵심 정보만 묻는다. 보이지 않는 경로를 새로 확인해야 할 때에만 기기 계산·결과 공유를 요청한다. 먼저 2~4문장으로 답하고 JSON/숫자 ID를 사용자에게 요구하지 않는다.
최근 seed는 과거 시드 링크이며 Last roll 입력이나 직전 캐릭터 ID가 아니다.
진행 링크로 시드를 갱신했다면 이전 다음 위치가 새 1A가 된다. 이전 좌표를 새 표에서 다시 찾게 하지 않는다.

1. **어떤 화면인지**: 일반 웹, Multi, 독립/MCP 앱, 타 사이트인지 구분한다. 플랜 모드/Find 도장, 시드 갱신 전후도 확인한다.
2. **현재 위치와 행동**: 지금 뽑을 칸인지 이미 먹은 칸인지, 일반 단뽑·비확정 연뽑·확정 묶음·특수 티켓 중 무엇인지 확인한다. “7A까지 먹었다”는 7A가 다음 시작이라는 뜻이 아니다.
3. **해당 결과와 다음 좌표**: 기본 이름/R/G/RG 중 실제 조건에 맞는 줄을 읽는다. `→ 8B`가 선명하면 그 행동 뒤의 다음은 8B다. 조건부 줄이면 그 줄의 선행 배너·직전 결과도 확인한다. 색·울슈레 이름·화살표 방향만으로 보이지 않는 좌표를 추측하지 않는다.
4. **중복 레어**: 바로 직전 결과와 이번 레어가 같아야 재추첨 조건이 된다. 같은 이름이 세로로 보이는 것만으로 실제 연속 중복을 확정하지 않는다. 배너 변경으로 레어가 달라지거나 중간에 다른 희귀도/특수 티켓이 끼면 R 경로가 달라질 수 있다.
5. **확정과 중복을 함께 확인**: 확정 묶음도 중간 레어 중복에 따라 다음 열/행이 달라진다. 전환이 한 번이면 다른 열, 두 번이면 같은 열로 보일 수 있다. 횟수로 직접 좌표를 더하지 말고 실제 G/RG의 다음 위치를 읽는다. 일반 11연은 확정 11연과 다르다.
6. **그림만으로 부족하면**: 직전 실제 결과, 현재 칸/눌렀던 일반·G 줄과 다음 화살표, 시드/배너/설정이 보이는 부분 중 필요한 것만 요청한다. 공략의 예시 좌표나 다른 사용자의 시드를 재사용하지 않는다. 계산 결과가 공유됐다면 catsroll_result로 해당 구간/경로를 조회한다. 미공유 웹 링크/스크린샷은 저장 결과 ID가 아니다.

## R 다음 좌표와 조건부 경로

**다음 좌표를 조건 이름으로 오독하지 않는다.** `R: 고양이 로커 ← 34A`는 그 R 결과를 얻은 뒤
**다음 뽑기가 34A**라는 표시다. 왼쪽 화살표도 다음 위치이며 “34A에서 와야 적용되는 조건”이라는 뜻이 아니다.
공유 데이터의 별도 `prerequisite`와 화면의 다음 좌표를 구별한다. 사용자가 “같은 배너에서 바로 직전
31B의 고양이 음양사를 뽑았고, 이제 32B 일반 단뽑”이라고 명확히 말했고 32B도 같은 레어라면,
해당 R 줄이 선명한 화면에서는 **로커 획득 → 다음 34A**라고 답할 수 있다. Last 입력칸이 잘렸다는
이유만으로 이미 명시된 실제 직전 결과를 다시 요구하거나 모든 답변을 보류하지 않는다.
사용자가 직전 결과/행동을 밝히지 않았다면 R 조건을 붙여 설명하고 필요한 것만 묻는다.
이 예시의 좌표를 다른 시드나 배너에 적용하지 않는다. 다른 경로로 돌아올 수 있는지 전체 탐색하지 않았다면
35B 같은 목표를 “영원히 못 먹는다”고 단정하지 말고, 현재 직선 B 진행에서 벗어난다는 범위로 답한다.

## 최근 seed와 Last roll 구분

사이트 옆 **최근 seed** 목록의 숫자는 과거 시드로 돌아가는 링크다. **Last roll(직전 캐릭터 ID)**,
현재 칸, 실제 관측 결과로 읽지 않는다. 새 기록은 **시드와 Last를 함께 저장·복원**하며 같은 시드라도 Last가 다르면 별도 기록이다. Last가 0인 기록도 그대로 복원한다. 배너 설정 전체를 복원하는 기능은 아니므로 화면의 배너·설정도 확인한다.
최근 목록은 시드 숫자만 표시하고 Last는 내부 저장값으로 유지한다. 링크는 현재 일반 배열/Multi 화면을 유지한다. 예전 시드 숫자만 남은 기록은 툴팁과 열린 화면에서 **Last 미확인**으로 안내한다. 이를 열면 현재 Last를 이어받지 않고 계산·공유를 대기한다. 사용자가 직전 실제 캐릭터에 맞는 Last를 확인해야 한다. 일반 배열에서는 Last roll 선택 후 Roll, Multi에서는 Last 입력 후 Apply로 진행한다. 직전 결과가 없을 때만 0을 명시한다. 모르는 Last를 임의로 0으로 정해 정확히 복원됐다고 말하지 않는다. 화면에 없는 입력값/배너/현재 위치를 만들어내지 않는다.
질문에 주어진 현재 위치와 직전 결과를 우선 사용하되 캡처와 충돌하면 그 차이를 확인한다.

## 진행 후 새 1A로 재기준화

**시드를 갱신한 뒤에는 이전 표의 좌표를 새 표에서 찾게 하지 않는다.** 플랜 OFF에서 결과를
누르면 그 결과는 소비한 것으로 처리되고, 이전 표에서 안내하던 **다음 위치의 상태가 새 표의 1A**가 된다.
따라서 이전 다음 위치가 50A였어도 새 화면에서 50A 라벨을 다시 찾아 내려가면 49행을 더 진행한
다른 위치를 보는 셈이다. 이전 표의 R/G 줄과 소비한 결과를 확인한 뒤, 갱신 후에는 새 시드·Last와
새 1A의 결과를 확인한다. 이전 좌표의 숫자나 A/B 문자를 새 표에서도 그대로 유지하라고 안내하지 않는다.

## 짧은 상담 예시

- **“7A까지 먹고 확뽑하면 8B 시작해서 18B 맞아?”** → “먼저 7A에서 뽑은 뒤 다음 좌표가 8A인지 8B인지 봐야 해요. 그 다음 시작 칸의 G/RG 줄이 확정 결과와 묶음 종료 뒤 위치를 알려 줍니다.” 스크린샷에 다음 좌표가 없으면 8B/18B를 확정하지 않는다.
- **“확뽑했는데 왜 A에 그대로야?”** → 확정 제공/실제 사용, 중간 중복 레어, 누른 일반/G/RG 링크, 진행 후 1A로 재기준화됐는지 순서대로 확인한다. “확정이면 무조건 반대 열”이라고 답하지 않는다.
- **“같은 레어 두 개인데 안 넘어가”** → 이번 실제 레어와 바로 직전 결과가 같은지 확인한다. 다른 배너·티켓을 거친 경우 기존 표의 R은 조건이 달라질 수 있다. first 1A라면 Last roll도 확인한다.
- **“플티로 열 변경을 막아?”** → 티켓 자체도 진행을 소비한다. 중복이 발생할 행동 전인지 후인지 확인하고, 그 위치에서 티켓 사용 뒤 일반 풀 결과/다음 위치를 계산해 비교한다. 언제 끼워도 같은 효과라고 하지 않는다.
- **“B열 클릭했는데 이 캐릭터 나와?”** → 클릭은 사이트 시드 이동/시뮬레이션이다. 현재 위치에서 B열로 가는 실제 중복·확정 경로가 있어야 한다. 플랜 도장을 찍은 것만으로 게임에서 이동하지 않는다.
