# 시드 찾기와 현재 위치

`prepared`는 입력 준비 완료일 뿐 계산 결과가 아니다. 후보 시드는 사용자가 앱에서 계산한 결과로만 설명한다.

## 시드와 A/B 위치

시드는 뽑기의 진행 상태를 나타내는 숫자다. 고정된 계정 ID가 아니며 실제로 뽑으면 달라진다. `1A`는 현재 기준 다음 A열 결과를 가리키는 상대 좌표다. 시드 숫자와 좌표를 혼동하지 않는다.

## 관측 입력과 준비

시드가 없거나 관측 기록을 아직 모으지 않았어도 `catsroll_prepare(mode="seek")`로 먼저 시드 찾기 화면을 열 수 있다. 이미 확인한 지역·배너와 결과가 있으면 준비 입력에 미리 채우고, 나머지는 화면에서 입력한다. 화면 준비는 시드 검색이 아니다. 실제 검색에는 지원되는 관측이 최소 한 개 필요하다.

검색에는 **한 배너에서 이어진 일반 단뽑 결과 최대 10개**를 쓴다. 한 개 이상으로 시작할 수 있지만 관측이 적으면 후보가 여러 개 나올 수 있으므로, 무조건 정확해지는 뽑기 수를 약속하지 않는다. 확정 11연·스텝업·플래티넘·레전드 티켓을 섞었거나 중간에 다른 뽑기를 한 기록은 이 입력 형식으로 처리하지 않는다.

1. 실제 게임 지역과 관측 당시 날짜·배너, 오래된 순서의 결과를 확인한다.
2. `catsroll_cats`로 각 이름과 진화 형태를 확인해 캐릭터 ID를 얻는다. 별명이 애매하면 확인한다.
3. 관측 당시 배너를 확인한다. 알고 있는 연속 관측은 `catsroll_prepare(mode="seek", rows=[배너], rolls=[관측 순서의 ID])`로 미리 채울 수 있다. 기록이 아직 없으면 먼저 `mode="seek"` 화면을 열고, 지원되는 관측을 한 개 이상 입력한 뒤 검색한다.
4. `prepared`는 입력 준비 완료라는 뜻이다. 후보·시드 계산은 사용자가 앱에서 실행한 결과로 설명하고, 준비 상태만으로 시드를 만들어내지 않는다.

## 검색 결과와 현재 위치

결과가 여러 후보·없음·중단이면 그대로 설명하고 하나를 임의로 고르지 않는다. `ambiguous`, `count: 2`는 두 번째 후보를 찾고 멈춘 **최소 2개** 상태일 수 있으므로 정확히 후보가 둘이라고 단정하지 않는다. `begin`/`end`가 `null`이면 후보 시드를 제시하지 않는다.

앱의 **관측 시작 시드**와 관측을 모두 뽑은 뒤의 **현재 시드**를 구분한다. 다음 뽑기는 현재 시드로 확인하고, 이후 추가로 뽑았다면 과거 시드를 현재 값처럼 사용하지 않는다. `last`는 직전 뽑기와 첫 결과의 레어 중복 판단에 쓰인다. 알면 직전 캐릭터를 확인하고, 모르면 불확실성을 밝힌다. 시드가 같아도 배너 풀·직전 결과가 다르면 첫 R 처리 등이 달라질 수 있다.

## 검색 실패 분기

| 상태 | 확인과 다음 행동 |
| --- | --- |
| 화면 연결 또는 계산 실패 | 후보 없음으로 해석하지 않는다. `troubleshooting`의 재시도·사이트 링크로 연결 문제를 먼저 복구한다. |
| 후보 없음 | 위의 관측 범위와 지역·당시 배너·ID·순서를 대조한다. 미래 배너를 과거 관측에 쓰거나 관측 전후를 섞지 않는다. 지원 가능한 관측 10개를 정확히 넣었다면 더 뽑게 하지 말고 배너 데이터·입력·오류를 확인한다. 후보 없음이나 중단은 시드 확정이 아니다. |
| 후보가 여러 개 | 모호한 결과라고 알린다. 아직 관측 한도가 남았다면 같은 배너의 연속 일반 관측을 더 확보해 다시 계산한다. 한도를 이미 채웠다면 추가 관측을 무작정 요구하지 말고 입력·배너 데이터·오류를 살핀다. |

관련 문서: `tracks`, `banners`, `troubleshooting`.
